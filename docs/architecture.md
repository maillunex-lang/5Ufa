# Архитектура

```
 Телефон: игра (Godot APK)          Телефон: админка (Godot APK)
        │  HTTPS/HTTP, WebSocket            │
        ▼                                   ▼
 ┌──────────────── VPS, Docker Compose (проект ufagame) ────────────────┐
 │  nginx :HTTP_PORT ── /content/files/*  → том contentstore (файлы)     │
 │        │          └─ /api/*, /health, /ws/* → api:8000               │
 │        ▼                                                             │
 │  api (FastAPI) ── postgres (данные игроков, релизы контента)         │
 │        └───────── redis (кэш, лимиты, чат, очереди)                  │
 │  backup — ежедневно pg_dump + архив контента → ./backups (14 дней)   │
 └──────────────────────────────────────────────────────────────────────┘
```

## Принципы

- **Сервер — источник истины.** Клиент не меняет ресурсы сам: любое действие — запрос,
  сервер проверяет и возвращает результат. Бой считается на сервере детерминированно
  (seed + фиксированный тик), клиент проигрывает лог.
- **Данные, а не код.** Герои, формулы, награды, тексты, интерфейс — это JSON-контент,
  проверяемый схемами из `/shared`. Поэтому админка меняет всё без обновления APK.
- **Один источник правды для схем** — `/shared/schemas`. Их используют сервер (проверка),
  админка (формы и проверка патчей) и клиент (структура данных).
- **Изоляция на VPS.** Наружу открыт один порт Nginx. Postgres и Redis — только во
  внутренней сети Docker. Имя проекта `ufagame` — все контейнеры и тома с этим префиксом,
  с другими вашими сервисами не пересекаются.
- **Неизменяемые релизы контента** + каналы `live`/`test` → черновик, тест, публикация, откат.

## Деплой

`push в main` → GitHub Actions: тесты (`ci.yml`) → SSH на VPS → `scripts/deploy.sh`:

1. Запомнить текущий коммит и версию схемы БД.
2. Дамп базы в `backups/predeploy/` (хранятся последние 10).
3. `git fetch` + `git reset --hard origin/main` (это надёжный аналог `git pull`: не застревает на конфликтах).
4. `docker compose build` → миграции `alembic upgrade head` → первичный импорт контента (только если база пустая).
5. `docker compose up -d`, пересоздание Nginx (подхват конфига).
6. Проверка `/health` до 90 секунд.
7. Ошибка на любом шаге → откат миграций до прежней версии, возврат кода на прежний коммит, перезапуск, повторная проверка.

## Почему так

| Решение | Причина |
|---|---|
| Файлы по SHA-256 вместо ZIP-пакетов | Качаются только изменённые файлы; докачка средствами HTTP Range; откат без копирования |
| `git reset --hard` вместо `git pull` | На VPS код не редактируется руками; pull может остановиться на конфликте и сорвать деплой |
| Postgres/Redis без портов наружу | Безопасность и отсутствие конфликтов с вашими сервисами |
| Отдельный контейнер бэкапов | Не зависит от cron на хосте, настраивается через `.env` |
