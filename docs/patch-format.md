# Формат ZIP-патча контента (версия 1)

> Статус: работает в админке (этап 6а): «ZIP-патч» → проверка и список изменений → «Применить в черновик».
> Схема `patch.json`: `shared/schemas/patch.schema.json`.

## Структура архива

```
my-patch.zip
├── patch.json                     ← обязательно, в корне архива
└── files/                         ← ресурсы; пути внутри files/ = пути в контенте
    └── heroes/hero_ural_batyr/
        ├── portrait.png
        ├── skeleton.json
        └── parts/arm_left.png
```

## patch.json

```json
{
  "id": "heroes-2026-11-batch1",
  "format_version": 1,
  "section": "heroes",
  "description": "Новые арты для Урал-батыра, правка статов Шурале",
  "author": "ИИ + проверка",
  "operations": [
    {
      "op": "update",
      "id": "hero_ural_batyr",
      "data": {"portrait": "heroes/hero_ural_batyr/portrait.png"},
      "files": ["heroes/hero_ural_batyr/portrait.png"]
    },
    {"op": "update", "id": "hero_shurale", "data": {"stats": {"atk": 120}}},
    {"op": "delete", "id": "hero_test_dummy"}
  ]
}
```

| Операция | Смысл | `data` |
|---|---|---|
| `add` | Добавить новый объект. Ошибка, если id уже есть | полный объект по схеме раздела |
| `update` | Изменить существующий. Ошибка, если id нет | только изменяемые поля; объекты сливаются, списки заменяются целиком |
| `delete` | Удалить объект. Ошибка, если на него ссылаются другие объекты | не нужен |
| `put_file` | Положить файл из архива по пути `path` (например новый фон) | не нужен, нужен `path` |
| `delete_file` | Удалить файл `path` из контента | не нужен, нужен `path` |

Как устроены объекты в каждом разделе (один файл на объект, массив в файле или один объект на раздел) —
`shared/admin/sections.json`. Например, герои: id = папка `heroes/<id>/`, фракции — элементы массива
`factions` в `factions/factions.json`, главный экран — один объект `hub`.

## Правила именования

- id: латиница в нижнем регистре, цифры и `_`, начинается с буквы: `hero_ural_batyr`, `chapter_3`.
- Пути файлов: только латиница в нижнем регистре, цифры, `_ - . /`. Без пробелов и кириллицы.
- Форматы: PNG/WebP (графика), OGG (звук/музыка), JSON (данные, UTF-8), TTF/OTF (шрифты).

## Процесс применения (этап 6)

1. Загрузка ZIP в админке → распаковка во временную папку (защита от путей `../`, лимит размера).
2. Проверка `patch.json` по схеме, затем каждого объекта — по схеме раздела.
3. Проверка ссылок: все файлы из `files` есть в архиве; все ссылки на героев/предметы существуют.
4. **Список изменений**: что добавится, изменится (было → стало), удалится. Ошибки — на русском, с указанием поля.
5. Предпросмотр в админке.
6. «Применить» → создаётся **черновой релиз** → публикация в канал `test` → проверка на тестовом аккаунте →
   «Опубликовать» (канал `live`) → при необходимости «Откатить» к любому прошлому релизу.

## Выгрузка раздела

«Выгрузить в ZIP» создаёт архив того же формата, где все объекты раздела записаны как `add`.
Его можно использовать как бэкап и как пример для ИИ.
