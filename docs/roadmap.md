## Этап 1 — план (выполнено)

1. Монорепозиторий со всеми папками.
2. Сервер FastAPI: `/health` (проверяет базу и Redis), `/api/v1/content/manifest`.
3. PostgreSQL + Redis в Docker, наружу не открыты. Миграции Alembic.
4. Хранилище контента по SHA-256 (одинаковые файлы хранятся один раз, откат мгновенный).
5. Релизы контента и каналы `live` (все игроки) / `test` (тестовые аккаунты) —
   основа для «черновик → тест → опубликовать → откатить».
6. Проверка контента по JSON Schema из `/shared` с сообщениями на русском.
7. Nginx: раздача файлов с поддержкой докачки (HTTP Range) и вечным кэшем, прокси к API, заготовка WebSocket.
8. Бэкапы: ежедневно база + контент, хранение 14 дней, скрипт восстановления.
9. Подключение к `https://tts-ufa.ru/games/server` через ваш основной Nginx (скрипт с резервной копией и автооткатом).
10. GitHub Actions: тесты на каждый push; при push в `main` — деплой по SSH с проверкой `/health` и автооткатом.
11. Скрипты для VPS: проверка портов, установка Docker, деплой, восстановление.

## Этап 1 — как проверить

Выполните [docs/setup-guide.md](setup-guide.md) до конца. Затем на VPS:

```bash
cd ~/ufagame
curl https://tts-ufa.ru/games/server/health
```
Ожидается: `{"status":"ok", ... "database":"ok","redis":"ok"}`.

```bash
curl https://tts-ufa.ru/games/server/api/v1/content/manifest
```
Ожидается: JSON с `"release":1`, `"base_url":"/games/server/content/files/"` и пакетами `core`, `tutorial`, `chapter_1`, `chapter_2`.

```bash
docker compose exec api python -m app.cli content status
```
Ожидается: `live : релиз №1 ...` и `test : релиз №1 ...`.

```bash
docker compose exec backup /bin/sh /backup/backup-now.sh && ls backups/
```
Ожидается: `[backup] готово: ...` и папка с датой в `backups/`.

С телефона откройте в браузере `https://tts-ufa.ru/games/server/health` — должен показаться тот же JSON.
Проверьте, что сайт tts-ufa.ru и сервис на порту 5000 работают как раньше.

Проверка автодеплоя: сделайте любой коммит в `main` (например, поправьте README на GitHub),
откройте вкладку **Actions** — задача **Deploy** должна стать зелёной, а `/health`
покажет новую `version` (хэш коммита).

## Этап 2 — план (выполнено)

1. Сервер: игроки и сессии (миграция 0002), вход гостем, привязка почты и пароля, вход по почте,
   обновление токенов, лимит попыток входа (Redis), бан, тестовые аккаунты → канал `test`.
2. Клиент Godot 4.7.2 (`/client`): экран загрузки, вход, манифест, загрузка обязательных пакетов
   с прогрессом в МБ, фоновые пакеты во время игры, докачка после обрыва (HTTP Range),
   проверка SHA-256, скачивание только изменённого, «Проверить файлы игры».
3. Главный экран: название и логотип из контента, аккаунт, привязка почты, вход в другой аккаунт.
4. GitHub Actions: сборка APK (`apk.yml`), подпись ключом из Secrets, выкладка в Releases;
   автопроверка клиента против настоящего сервера (`ci.yml` → `client-e2e`) перед каждым деплоем.

## Этап 2 — как проверить

1. Создайте ключ подписи и 3 секрета — [apk-signing.md](apk-signing.md), шаги 1–3.
2. Соберите APK: Actions → APK → Run workflow (шаг 4) и установите на телефон.
3. Запустите игру. Ожидается: экран «Подключение к серверу…» → «Загрузка обновлений» с полосой
   и «N МБ из M МБ» → главный экран с логотипом, `[НАЗВАНИЕ]` и `Путник-NNNN · #NNNN · гость`.
4. Нажмите «Привязать почту», введите почту и пароль → «Почта привязана».
5. На втором телефоне (или после удаления и переустановки игры) — «Войти в другой аккаунт» →
   та же почта → номер игрока тот же.
6. Тестовый канал: на VPS `docker compose exec api python -m app.cli player set-test <номер>`,
   перезапустите игру — под именем появится «ТЕСТОВЫЙ».
7. Докачка: включите режим полёта во время загрузки, затем выключите и нажмите «Повторить» —
   загрузка продолжится с того же места.
