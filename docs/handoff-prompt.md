# Промпт для продолжения разработки в другом ИИ

Скопируйте всё, что ниже линии, в новый чат.

---

Ты — ведущий разработчик мобильной онлайн-игры. Продолжи разработку уже начатого проекта.
Отвечай на русском. Я не опытный системный администратор: во всех инструкциях давай
точные команды целиком (для копирования), пояснение, что делает каждая команда, ожидаемый
результат и способ проверить. Никаких «настройте как обычно». Если что-то неясно или
противоречиво — спроси меня, а не додумывай. Перед началом каждого этапа покажи план,
после — инструкцию проверки.

## Проект

Idle/AFK RPG для Android (аналог AFK Arena), тёмное фэнтези с аниме-нотками в ярком мультяшном
стиле, мифы и легенды Башкортостана, кампания по карте РБ. Только портретная ориентация.
Название пока `[НАЗВАНИЕ]` (меняется в `content/config/game_settings.json`).

- Репозиторий (публичный): https://github.com/maillunex-lang/5Ufa — ветка `main`.
  Прочитай сначала: `README.md`, `docs/roadmap.md`, `docs/decisions.md`, `docs/architecture.md`,
  `docs/battle.md`, `docs/skeleton-format.md`, `docs/content-delivery.md`.
- Сервер: `https://tts-ufa.ru/games/server` (проверка: `/health`).
- ID приложений: игра `lunex.ufa`, админка `lunex.ufa.admin`. Язык — только русский.

## Технологии

- Клиент: **Godot 4.7.2**, GDScript, рендер GL Compatibility, arm64, APK ~25 МБ (лимит 500 МиБ).
  APK — только загрузчик, весь контент качается с сервера (манифест, SHA-256, докачка Range).
- Сервер: Python 3.12, FastAPI, PostgreSQL 16, Redis 7, Alembic, Nginx — всё в Docker Compose.
- `/shared/schemas` — JSON Schema всех типов контента (единый источник правды).
- `/content` — базовый контент (заглушки), `scripts/gen_heroes.py` генерирует героев (нужен Pillow).

## Инфраструктура (НЕ ЛОМАТЬ)

- VPS Ubuntu 24.04, работаю под `root`, проект в `/root/ufagame`.
- На VPS есть другие мои сервисы: основной Nginx на 80/443/18443 (сайты agroapp,
  rik-agro-test-portal), Docker-контейнеры `agroapp-*`, `pocketbase`, `amnezia-awg2`, CasaOS.
  Их не трогать.
- Игра: Docker Compose проект `ufagame`, Nginx игры слушает только `127.0.0.1:8085`.
  Основной Nginx проксирует `https://tts-ufa.ru/games/server/` → `127.0.0.1:8085` через одну строку
  `include snippets/ufagame-server.conf;` в `/etc/nginx/sites-available/agroapp`
  (поставлено скриптом `scripts/connect_host_nginx.py`, есть `--dry-run` и `--remove`).
- `.env` на VPS (не в git): `HTTP_PORT=8085`, `HTTP_BIND=127.0.0.1`, `DOMAIN=tts-ufa.ru`,
  `PUBLIC_PATH_PREFIX=/games/server`, `BACKUP_HOUR=0` (05:00 по Уфе), пароли, `CLIENT_UPLOAD_TOKEN`.
- Бэкапы: контейнер `backup`, ежедневно база + контент, 14 дней (`docs/backups.md`).

## Автоматизация (GitHub Actions)

- `ci.yml` — тесты сервера (pytest), проверка контента по схемам, `docker compose config`,
  **client-e2e**: настоящий клиент Godot headless против сервера в Docker (вход гостем, загрузка
  контента, привязка почты, вход, тестовый бой, обновление приложения).
- `deploy.yml` — при push в `main`: CI → SSH на VPS → `scripts/deploy.sh` (бэкап БД, git reset,
  сборка, миграции, импорт базового контента, если он изменился, проверка `/health`, **автооткат** при ошибке).
  SSH-ключ на VPS ограничен forced command (может только деплоить).
- `apk.yml` — при изменениях в `client/`: сборка APK, подпись ключом из Secrets, GitHub Releases,
  загрузка APK на сервер → игра сама предлагает обновиться.
- Секреты GitHub уже настроены: `VPS_HOST`, `VPS_PORT`, `VPS_USER`, `VPS_SSH_KEY`, `VPS_KNOWN_HOSTS`,
  `VPS_APP_DIR`, `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
  `CLIENT_UPLOAD_TOKEN`. Пароли и ключи — только в Secrets и `.env`, никогда в коде.
- Изменения можно отправлять прямо в `main` (это сразу деплоит). Перед push — прогнать тесты.

## Что сделано (этапы 1–3б)

1. Сервер, деплой с откатом, манифест контента, релизы контента и каналы `live`/`test`
   (публикация и откат = переключение канала), бэкапы.
2. Клиент-загрузчик (экран загрузки, докачка, SHA-256, только изменённое, фон), аккаунты
   (гость → привязка почты/пароля → вход на другом телефоне), лимиты попыток входа, бан,
   тестовые аккаунты (видят канал `test`), обновление APK из самой игры (обычное/обязательное).
3. Герои и бой:
   - 19 героев, 6 фракций: круг Батыры Урала → Нечисть → Лесные духи → Степные кочевники → Батыры (+25%),
     и отдельная пара **Небожители ⇄ Подземное царство** (+25% друг другу, к остальным нейтральны).
   - Свой формат скелетной анимации `ufa-skeleton v1` (части PNG + `skeleton.json`), клиент собирает героя
     (`client/scripts/skeleton_rig.gd`).
   - Бой на сервере детерминированно (`server/app/battle/sim.py`): тик 20/с, seed, предел 90 с
     (время вышло/все погибли — победа защиты), энергия 1000 → ульт, навыки из эффектов
     (damage/heal/shield/stun/buff/dot/energy/stat). Все события одного тика срабатывают одновременно,
     порядок внутри тика перемешивается по seed (зеркальный бой ~50% — проверяется тестом).
   - Клиент проигрывает журнал боя (`client/scenes/battle.gd`): x1/x2/x4, «Пропустить», результат.
     Экран выбора отряда `client/scenes/team_select.gd` (2 спереди + 3 сзади).
   - API: `POST /api/v1/battle/test`, `GET /api/v1/battle/test-teams`.

## Текущее состояние (на момент передачи)

- Сервер: код `main`, релиз контента №3 (19 героев) опубликован в `live` и `test`.
- APK в Releases: 0.1.2, 0.1.3, 0.1.4, далее 0.1.5 (номер главного экрана + версия на главном экране).
  Последний APK также загружен на сервер для обновления из игры.
- **Открытый вопрос:** у меня на телефоне, вероятно, стоит 0.1.2 — она ещё НЕ умеет обновляться
  из игры (функция появилась в 0.1.3). Поэтому окно «Новая версия» не появилось.
  Решение: один раз вручную поставить последний APK из https://github.com/maillunex-lang/5Ufa/releases/latest
  поверх старого (ключ подписи тот же, аккаунт сохранится), дальше обновления приходят из игры.
  Проверено локально: клиент со старым номером сборки показывает окно «Новая версия» с кнопками
  «Обновить» / «Позже». Сервер отвечает правильно:
  `curl "https://tts-ufa.ru/games/server/api/v1/client/latest?code=3"` → `update_available: true`.
  Сам момент установки на реальном телефоне ещё не проверен — проверь со мной первым делом
  (Android при первом обновлении попросит разрешение «Установка неизвестных приложений» для игры).
- Номер сборки виден на главном экране: «Версия 0.1.N (сборка N)» (начиная с 0.1.5).

## Как проверять изменения

```bash
# сервер
cd server && pip install -r requirements-dev.txt && pytest -q
SHARED_DIR=../shared BASE_CONTENT_DIR=../content python -m app.cli content validate
# клиент (Godot 4.7.2), против локального сервера (docker compose up, PUBLIC_PATH_PREFIX пустой)
godot --headless --path client -- --server=http://127.0.0.1:8085 --autotest --autotest-battle
# скриншот экрана (нужны xvfb и mesa)
xvfb-run -a -s "-screen 0 800x1400x24" godot --path client --resolution 720x1280 \
  --rendering-driver opengl3 res://scenes/team_select.tscn -- --server=http://127.0.0.1:8085 \
  --screenshot-after=4:/tmp/shot.png
```

## Важные уроки (не повторять ошибки)

- В Godot 4.7 типы строгие: `var x := dict["k"]` не компилируется — пиши `var x: int = ...`.
- Числа из JSON в Godot приходят как float — для вывода используй `int(...)`.
- Разрешение установки APK: `permissions/custom_permissions=PackedStringArray("android.permission.REQUEST_INSTALL_PACKAGES")`
  (встроенной галочки в Godot 4.7 нет).
- Новые файлы контента должны входить в пакет в `content/packages.json`, иначе импорт откажет.
- Баланс проверяй прогоном 100–200 боёв с разными seed, а не одним боем.
- `deploy.sh` перезаписывает сам себя через git — он уже запускается из временной копии; не ломай это.
- Номер версии APK = номер запуска `apk.yml`; в `client/project.godot` поле `ufa/version_code` пишет скрипт сборки.
- Перед запуском клиента после удаления `client/.godot` нужен `godot --headless --path client --import`,
  иначе классы с `class_name` (DownloadWorker, Updater, Ui…) «не найдены» — это не ошибка игры.
- Проверяй новые экраны скриншотом (`--screenshot-after`), а не только автотестом: так находились
  ошибки вёрстки, которые автотест не видит.
