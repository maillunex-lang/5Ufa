# Промпт для продолжения разработки в другом ИИ

Скопируйте всё, что ниже линии, в новый чат. Если у ИИ нет доступа к репозиторию — дайте ему ссылку
на репозиторий или приложите архив проекта.

---

Ты — ведущий разработчик мобильной онлайн-игры. Продолжи разработку уже начатого проекта.

## Как со мной работать (обязательно)

- Отвечай на русском. Я не системный администратор: во всех инструкциях давай точные команды
  целиком (для копирования), объясняй, что делает каждая команда, какой результат ожидается
  и как проверить.
- Перед каждым этапом покажи план и дождись моего «да». После этапа — пошаговая проверка на телефоне.
- Если что-то в задании неясно или противоречиво — спроси меня, а не додумывай.
- Решения по дизайну и функциям спрашивай опросом: 3–4 вопроса за раз, у каждого варианты,
  рекомендованный — первым с пометкой «(Рекомендуется)».
- Не обещай, что обновление, уведомление или бой работают на реальном телефоне, пока это
  действительно не проверено. Пиши честно, что проверено автотестом, а что ещё нет.
- **Секреты и пароли — только в GitHub Secrets и `.env` на сервере.** Никогда не помещай их в код,
  логи, промпты или переписку и не проси меня прислать их в чат.
- Перед каждым push прогоняй подходящие тесты. Проверенные изменения можно отправлять прямо
  в `main` — это сразу запускает деплой на сервер.

## Проект

Idle/AFK RPG для Android (портретная ориентация), мифы и легенды Башкортостана (Урал-батыр, Хумай,
Шульген, Аждаха, Шурале…), кампания по местам РБ (Уфа, Иремель, Шульган-Таш, Янган-Тау, Аслыкуль).
Стиль — аниме-фэнтези, цвета зелёный + золото, башкирский орнамент. Только русский язык.
Название пока `[НАЗВАНИЕ]` (меняется в `content/config/game_settings.json`).

- Репозиторий: https://github.com/maillunex-lang/5Ufa — ветка `main` (рабочая ветка этапов — `stage6c2`,
  она совпадает с `main`).
- **Сначала прочитай:** `README.md`, `docs/roadmap.md`, `docs/decisions.md` (все мои решения и ответы
  на опросы — главный документ), `docs/architecture.md`, `docs/admin.md`, `docs/battle.md`,
  `docs/skeleton-format.md`, `docs/content-delivery.md`, `docs/patch-format.md`, `docs/art-prompts.md`.
- Сервер: https://tts-ufa.ru/games/server (проверка: `/health` — показывает версию кода).
  Веб-админка: https://tts-ufa.ru/games/server/admin/
- ID приложений: игра `lunex.ufa`, админка `lunex.ufa.admin` (менять нельзя после RuStore).

## Технологии

- Клиент: **Godot 4.7.2**, GDScript, рендер GL Compatibility. Игра и админка — один проект `client/`
  (админка — `client/admin/`, фича `admin`, свой пресет экспорта; в APK игры `admin/*` исключён).
  APK — только загрузчик: весь контент (JSON, картинки) качается с сервера по манифесту (SHA-256, докачка).
- Админка: APK (телефон) + веб-версия того же проекта (экспорт Web без потоков, лежит на сервере `/admin/`).
- Сервер: Python 3.12, FastAPI, async SQLAlchemy, Alembic (миграции до 0008), PostgreSQL 16, Redis 7,
  Nginx — всё в Docker Compose. Pillow, numpy, opencv-python-headless (нарезчик героев).
- `shared/schemas/` — JSON Schema всех типов контента (единый источник правды);
  `shared/admin/sections.json` — разделы админки; `shared/admin/rig_templates.json` — шаблоны 2D-скелета.
- `content/` — базовый контент. Контент в игре — релизы (каналы `live` и `test`); правки из админки идут
  в черновик → тест → публикация → откат. Деплой переносит изменения репозитория поверх, не затирая
  правки из админки.

## Инфраструктура (НЕ ЛОМАТЬ)

- VPS Ubuntu 24.04 (Германия), работаю под `root`, проект в `/root/ufagame`.
- На VPS работают другие мои сервисы (основной Nginx на 80/443, сайты, Docker-контейнеры, порт 5000
  и др.). **Их конфигурацию, контейнеры, тома и порты не трогать. Правила основного Nginx не менять.**
- Игра: Docker Compose проект `ufagame`, Nginx игры слушает только `127.0.0.1:8085`.
  Основной Nginx проксирует `https://tts-ufa.ru/games/server/` → `127.0.0.1:8085` одной строкой
  `include snippets/ufagame-server.conf;` (поставлено `scripts/connect_host_nginx.py`).
- `.env` на VPS (не в git): порты, домен, пароли, `CLIENT_UPLOAD_TOKEN`, `GEMINI_API_KEY`
  (ключ Gemini, работает с VPS — проверка `docker compose exec api python -m app.cli ai check`).
- Бэкапы: контейнер `backup`, ежедневно база + контент, 14 дней; в админке — список и «бэкап сейчас».

## Автоматизация (GitHub Actions)

- `ci.yml`: тесты сервера (pytest, ~80 тестов), проверка контента по схемам, сборка APK игры, APK
  админки и веб-админки, **client-e2e** — настоящий клиент Godot headless против сервера в Docker:
  вход, загрузка контента, бои, кампания, герои, снаряжение и автотесты админки (ADMIN, ANIM, CUT,
  SCREENS, LIVE), обновление приложения.
- `deploy.yml`: push в `main` → CI → SSH на VPS → `scripts/deploy.sh` (бэкап БД, обновление кода,
  сборка, миграции, импорт базового контента, проверка `/health`, **автооткат** при ошибке).
  Необязательный секрет `GEMINI_API_KEY` записывается в `.env` через вход SSH (не в командной строке).
- `apk.yml`: сборка и подпись APK игры и админки, GitHub Releases, загрузка на сервер → игра сама
  предлагает обновиться; веб-админка загружается на сервер.
- Секреты GitHub настроены (VPS_*, ANDROID_KEYSTORE_*, CLIENT_UPLOAD_TOKEN). Новые секреты называй мне,
  а вставляю их я сам.

## Что сделано

- **1–2.** Сервер, деплой с откатом, релизы контента, бэкапы; клиент-загрузчик, аккаунты (гость → почта →
  вход на другом телефоне), бан, тестовые аккаунты, обновление APK из игры.
- **3.** 25 героев, 6 фракций; бой считает сервер детерминированно (`server/app/battle/sim.py`), клиент
  проигрывает журнал; ручные ульты по WebSocket при выключенном «Авто». Герои сейчас **2D**: формат
  `ufa-skeleton v1` (части PNG + `skeleton.json`), сборка в `client/scripts/skeleton_rig.gd`.
- **4.** Кампания (5 глав), AFK-сундук, быстрая награда, уведомления.
- **5.** Уровни, Кристалл резонанса, вознесение, призыв с гарантом и баннерами, снаряжение.
- **6.** Админка: вход с лимитом и 2FA, роли, журнал; разделы контента (формы по JSON Schema и «как JSON»),
  черновик/тест/публикация/откат, ZIP-патчи и «Промпт для ИИ»; игроки (ресурсы с причиной, тест, бан),
  бэкапы, версии APK; предпросмотр; «Картинки игры» по экранам.
- **6в.** Конструктор экранов (`ui/screens/*.json`, `client/scripts/screen_layout.gd`) и правка прямо в игре
  долгим нажатием; экран под любой телефон (якоря, безопасные зоны); герой целиком в ZIP; скины
  (выдача игрокам, выбор, видны в бою); редактор 2D-анимации; **нарезчик героя** из рисунка (авто, ИИ
  Gemini по подходу spine-animation-ai — вендорный код с лицензией PolyForm Noncommercial в
  `server/app/vendor/spine_ai/`, кисть и многоугольник, скелет из 3 шаблонов).
- Опрос по интерфейсу (28 вопросов) записан в `docs/decisions.md` — скелет интерфейса всех экранов
  (этапы 7а–7в) по нему ещё **не сделан**. Промпты для генерации всех картинок — `docs/art-prompts.md`
  (собирается `scripts/gen_art_prompts.py`).

Что ещё не проверено мной на реальном телефоне: нарезчик героя (6в-3), особенно нарезка через ИИ
Gemini (в тестах ответ Gemini подменён); часть этапов 4–6 отмечена в `docs/roadmap.md` как
«готово к проверке».

## Следующая задача: переход героев и врагов на 3D (план утверждён, работа НЕ начата)

Мои решения (подробно — `docs/decisions.md`, строки «3D: …»):

- В 3D — герои и враги (бой, экран героя, появление при призыве). Город, меню, окна остаются 2D.
- Бой **строго сбоку, как сейчас** (2.5D); фон — рисованный 2D + 3D-земля с тенями.
- Стиль — **аниме-тун** (cel-shading, контур). Настройка «Графика» высокая/низкая, по умолчанию
  выбирается сама по скорости телефона (низкая: без контура и теней, 30 кадров, меньше частиц).
- Модели делаю я в **Meshy AI** (премиум): 2D-арт героя → Image to 3D → авториг Meshy → анимации
  из библиотеки Meshy → выгрузка **GLB**. Бюджет: до 10 тыс. треугольников, текстура 1024.
- Модель загружаю **в админке** (GLB; если Meshy отдаёт анимации отдельными файлами — ZIP из нескольких
  GLB). Игра скачивает модель как обычный контент, без обновления APK (загрузка GLB во время работы —
  `GLTFDocument`).
- В админке для 3D-героя: предпросмотр (крутить пальцем, проигрывать анимации); сопоставление анимаций
  Meshy с `idle/walk/attack/skill/ultimate/hit/death/victory` (подстановка по названиям + выпадающие
  списки, отметка момента удара) и таблица «какие движения Meshy брать для каждой роли»; размер,
  поворот, высота над землёй; точки «откуда снаряд / куда попадают / над головой» по костям.
- Нечеловеческие герои (змей, птица, дерево, дух): по возможности человекоподобный облик, иначе модель
  без скелета и движения кодом (покачивание, рывок, вспышка).
- Переход **по одному герою**: есть модель — в бою 3D, нет — прежний 2D. После перехода всех героев
  2D-редакторы, нарезчик и 2D-скелеты удаляются (этап 6в-4 отменён).
- Враги: герои + отдельные монстры и боссы глав (свой раздел в админке).
- Портреты и полный арт остаются рисованными 2D (кнопка «снять портрет с 3D» — по желанию).
  Скин — отдельный GLB.
- Эффекты — 3D-частицы из кода по фракциям/стихиям.
- Пилот — **один герой: Урал-батыр**. Порядок: сначала админка и инструкция Meshy.

Этапы:
1. **3D-1** — `docs/meshy-guide.md` (пошагово для Урал-батыра: арт по промпту → Meshy Image to 3D,
   настройки, Rigging, выбор анимаций по ролям, выгрузка GLB; промпты Meshy для всех героев) +
   сервер (приём GLB/ZIP, проверка: треугольники, текстуры, анимации, кости, предупреждения) +
   админка «Герой → 3D-модель» (предпросмотр, сопоставление анимаций, размер/поворот/высота, точки,
   скины GLB) + схема `hero.json` для модели.
2. **3D-2** — 3D в бою: вид сбоку, тун-шейдер, тени, 2D запасной для героев без модели, «Графика»,
   движения кодом для моделей без скелета.
3. **3D-3** — 3D-частицы эффектов и снарядов, живая модель на экране героя, появление при призыве.
4. **3D-4** — монстры и боссы (раздел админки, главы кампании, промпты Meshy).
5. **3D-5** — уборка 2D после перехода всех героев.

Начни с того, что прочитаешь документы и код, покажешь мне план **3D-1** подробно и спросишь,
что неясно (например: как Meshy выгружает анимации — одним GLB или отдельными файлами; я пришлю
пример модели). Код не пиши, пока я не скажу «да».

## Как проверять изменения

```bash
# сервер
cd server && pip install -r requirements-dev.txt && pytest -q
SHARED_DIR=../shared BASE_CONTENT_DIR=../content python -m app.cli content validate
# локальный сервер для клиента: в корне cp .env.example .env (заполнить пароли, PUBLIC_PATH_PREFIX пустой),
# docker compose up -d --build; docker compose exec api alembic upgrade head;
# docker compose exec api python -m app.cli content import --if-empty --publish
# docker compose exec -e ADMIN_PASSWORD=... api python -m app.cli admin create owner
# клиент (Godot 4.7.2)
godot --headless --path client --import
godot --headless --path client -- --server=http://127.0.0.1:8085 --autotest --autotest-battle
# админка: автотест и снимок экрана нужного раздела
godot --headless --path client res://admin/admin_main.tscn -- --server=http://127.0.0.1:8085 \
  --admin-autotest=owner:ПАРОЛЬ --admin-show=cuttest
xvfb-run -a -s "-screen 0 720x1600x24" godot --path client --resolution 720x1600 \
  res://admin/admin_main.tscn -- --server=http://127.0.0.1:8085 --admin-autotest=owner:ПАРОЛЬ \
  --admin-show=hero --screenshot-after=20:/tmp/shot.png
```

## Важные уроки (не повторять ошибки)

- Godot 4.7: предупреждения о типах считаются ошибками — `var x := dict["k"]` не компилируется,
  пиши `var x: int = ...`. Числа из JSON приходят как float — для вывода `int(...)`.
- В веб-версии админки: `accept_gzip=false` (браузер сам распаковывает), адрес сервера берётся из
  `window.location`, символы ← ▾ ✕ шрифт не показывает — только ASCII.
- Новые файлы контента должны попадать в пакет из `content/packages.json`, иначе импорт откажет.
- id элементов экрана в `ui/screens/*.json` должны быть уникальны (`scripts/gen_screens.py` проверяет).
- После пересоздания контейнера api пересоздавай и nginx (деплой это делает) — иначе 502.
- API в контейнере работает от uid 1000: пиши только в тома, где у него есть права.
- `deploy.sh` перезаписывает сам себя через git — он запускается из временной копии; не ломай это.
- Проверяй новые экраны снимком экрана (`--screenshot-after`) на 720×1600, а не только автотестом:
  так находятся кнопки без надписей, наезды и элементы, до которых не дотянуться пальцем.
- Баланс проверяй прогоном 100–200 боёв с разными seed.
- Лицензия spine-animation-ai — только некоммерческая: до коммерческого релиза нужна лицензия
  Genielabs или замена кода (при переходе на 3D нарезчик и так удаляется).
