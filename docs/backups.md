# Бэкапы и восстановление

## Автоматически

Контейнер `backup` каждый день в `BACKUP_HOUR` (UTC, по умолчанию 3:00 UTC = 8:00 по Уфе) создаёт папку
`backups/ГГГГ-ММ-ДД_ЧЧММ/`:

| Файл | Что это |
|---|---|
| `db.dump` | Вся база PostgreSQL (игроки, релизы контента, настройки) |
| `content.tar.gz` | Все файлы контента (графика, звуки, данные) |
| `SHA256SUMS` | Контрольные суммы для проверки целостности |

Бэкапы старше `BACKUP_RETENTION_DAYS` (14) удаляются автоматически.
Дополнительно перед каждым деплоем делается дамп базы в `backups/predeploy/` (последние 10).

Чтобы бэкап был по времени Уфы в 4 ночи, поставьте в `.env` `BACKUP_HOUR=23` (23:00 UTC = 04:00 Уфа),
затем `docker compose up -d backup`.

## Вручную

```bash
cd ~/ufagame
docker compose exec backup /bin/sh /backup/backup-now.sh
ls -la backups/
```
Ожидается: `[backup] готово: /backups/...` и новая папка.

## Восстановление

```bash
bash scripts/restore.sh                    # список бэкапов
bash scripts/restore.sh 2026-11-03_0300    # восстановить выбранный
```
Скрипт проверит контрольные суммы, спросит подтверждение (нужно ввести `YES`),
сделает свежий бэкап текущего состояния, затем восстановит базу и файлы.
На этапе 6 то же самое будет кнопкой в админке.

## Копия во внешнее хранилище (позже)

Предусмотрено место: если появится исполняемый файл `deploy/backup/remote-upload.sh`, он будет
вызываться после каждого бэкапа с путём к папке бэкапа. Для Яндекс Диска его сделаем через
`rclone` (WebDAV) — включим, когда скажете; понадобится пароль приложения Яндекса,
он будет храниться только в `.env`.

## Посмотреть, что бэкапы работают

```bash
docker compose logs --tail=20 backup
```
Ожидается: строка `сервис бэкапов запущен ...`, а после первого срабатывания — `готово: ...`.
