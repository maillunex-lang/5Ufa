# Передача разработки (HANDOFF)

Дата: 2026-11-04. Читайте вместе с `AGENTS.md` и `docs/ROADMAP.md`.

## Что за проект
Онлайн-RPG 5×5 с коллекцией героев и полным автобоем. Android, вертикальная ориентация, клиент на Godot 4.4.1 (GL Compatibility, 720×1280), сервер Node 22 (без внешних зависимостей, `node:sqlite`) на VPS владельца, адаптивная веб-админка без сборки. Репозиторий публичный: https://github.com/maillunex-lang/5Ufa. Владелец пишет по-русски, отвечайте по-русски.

## Правила владельца
- Минимум действий с его стороны: всё, что можно сделать самим (PR, слияние при зелёном CI, проверка деплоя), делайте сами. Слияние PR при зелёной сборке разрешено.
- Не имитировать готовность: заглушки помечайте, недоступное не рисуйте рабочим.
- Числа баланса тестовые, лежат в данных (`content/game.json`).
- Секреты и данные игроков не коммитить и не печатать в журналы.
- Не трогать `/root/ufagame` на VPS кроме деплоя и чужие проекты. Деплой только через `scripts/deploy.sh` (GitHub Actions).
- Чужие ресурсы только с записью в `docs/licenses.md`. Фоны Kalponic в репозиторий не класть.
- Блокировки среды (например, скачивание) не обходить; нужно явное разрешение владельца.

## Как это работает
- `main` → `.github/workflows/deploy.yml` (тесты, затем SSH на VPS, `scripts/deploy.sh`, docker compose, проверка `/health`). Сервер: `https://tts-ufa.ru/games/server/`, админка: `.../admin/`, логин `owner`, пароль на VPS: `./scripts/admin-password.sh`.
- APK: `.github/workflows/client.yml` публикует prerelease `client-test-N` с `5ufa-test.apk`. Ключ подписи в `deploy/test-signing/` тестовый.
- Контент: `content/game.json` (схема и проверки в `server/src/content.js`), версии в таблице `content_versions`, файл-зерно импортируется только при изменении хеша. Правки админки сохраняются как новая версия.
- Бой: детерминированная симуляция на сервере (`server/src/battle.js`), клиент воспроизводит события (`client/battle.gd`). Контракт: `docs/api.md`, `docs/battle-rules.md`.
- Медиатека: `docs/media.md`; 3D-просмотр в админке: `admin/viewer.js` (three.js, `admin/vendor`).

## Проверка
- Сервер: `cd server && npm test && npm run economy` перед каждым PR.
- Клиент: headless Godot 4.4.1 под xvfb, скриншоты, временные flow-сценарии.
- Админка: Playwright (Chromium) с флагами `--use-angle=swiftshader --enable-unsafe-swiftshader` для WebGL.
- Не проверялось на настоящем телефоне.

## Ловушки
- Числа с сервера приходят как `1.0`: в GDScript сравнивайте через `int()`.
- `set_anchors_preset` не растягивает; нужен `set_anchors_and_offsets_preset`.
- Billboard-материалам нужен `billboard_keep_scale = true`.
- В админке `display:flex` перебивает `hidden` (есть правило `[hidden]{display:none!important}`); читайте черновик через `acc()` без мутаций.
- Внутри контейнера `PORT=8080`, снаружи 8085.
- Модели из разных источников в разных единицах: габариты считает `fit()` по сетке и костям.
- Ветка сессии после слияния PR пересоздаётся от `origin/main`.
- Прямой SSH к VPS из облачной среды закрыт.

## Известные ограничения
Бой не закрепляет версию ресурсов; `data/media` вне бэкапа; изображения в медиатеку не загружаются (есть папка и теги у GLB); скорость x4 закрыта до VIP; у моделей KayKit лишнее оружие (скрывается `visual.hide`); карта не подгружается частями.
