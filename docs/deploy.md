# Развёртывание тестового окружения

Требуется на VPS только Docker. Скрипты не трогают чужие контейнеры, порты и nginx-конфиги; порт выбирается свободный (с 18080) и слушает только 127.0.0.1. Публикация — через nginx на https://tts-ufa.ru/games/.

## Первый раз (одна команда на VPS, из каталога репозитория)
```
sudo ./deploy/first-install.sh
```
Скрипт соберёт и запустит сервер на порту 8080 и напечатает логин/пароль владельца админки
(также лежат в томе: `docker compose exec server cat /data/ADMIN_INITIAL_PASSWORD.txt`).
Админка: `http://<адрес-VPS>:8080/admin/`. Смените пароль после входа и удалите файл.
Свой пароль можно задать заранее в `.env` (`ADMIN_PASSWORD=`), см. `.env.example`.

## Каждое обновление (автоматизируется вашей синхронизацией с GitHub)
После того как ваша выгрузка из GitHub обновила файлы на VPS, нужно выполнить **одну** команду:
```
./deploy/redeploy.sh
```
Она пересобирает контейнер, ждёт `/health` и не трогает данные игроков (docker volume `5ufa-data`).
Если ваша синхронизация умеет запускать команду после pull (hook/cron/systemd path), укажите именно её.
Изменение `content/game.json` создаёт новую версию контента при старте; идущие бои остаются на старой.

## HTTPS
Для боевого окружения нужен домен и TLS (reverse proxy, например Caddy/nginx перед портом 8080).
Админка по голому HTTP передаёт пароль открытым текстом — для реальных данных не использовать.
Сервер читает `X-Forwarded-For` для ограничения попыток входа, поэтому порт 8080 за прокси лучше
закрыть снаружи (`BIND=127.0.0.1` в `.env`).

## Бэкапы
Ежедневный SQLite-бэкап в `/data/backups` (хранится 14, `BACKUP_KEEP`), ручной — кнопка в админке.
Восстановление: остановить сервер, заменить `/data/game.db` выбранной копией. Копии перед опасными действиями — вместе с редактором игроков (этап 5).
