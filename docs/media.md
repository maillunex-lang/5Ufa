# Медиатека моделей и анимаций (A-4, первая часть)

- **Что это.** Файлы GLB (модели и файлы анимаций) с логическими именами. Герои и враги ссылаются на модель по имени (`visual.model`), на файлы анимаций по имени (`visual.anim_files`). Файлы лежат в `data/media/<sha256>.glb` и не меняются.
- **Вшитые модели.** При первом запуске сервер добавляет в медиатеку модели из `client/assets/models` (в образе `/app/seed-models`) как версию 1 с пометкой «вшита». Клиент для них файл не качает: берёт свою копию.
- **Замена графики.** Загрузка файла под существующим именем создаёт новую версию, **неактивную**. Её можно посмотреть в 3D, затем «Сделать активной». До включения игроки получают прежнюю. Откат: «Сделать активной» у старой версии. Все действия пишутся в журнал (`media_upload`, `media_activate`).
- **Клиент.** При входе приходит манифест (`media` в `/api/content`). Недостающие невшитые файлы скачиваются в `user://media` с проверкой хеша; крупная загрузка (больше 10 МБ) требует подтверждения. Если не скачалось или игрок отказался, используются вшитые модели. Модель загружается из файла прямо в игре (`GLTFDocument`).
- **Ограничения.** Файл до 40 МБ, до 200 тыс. треугольников и 300 костей. Для анимаций из отдельного файла скелет должен совпадать по именам костей. Пока не включено: бой не закрепляет версию ресурсов (только версию контента), резервное копирование файлов медиатеки (бэкап копирует базу, а не `data/media`), загрузка изображений и фонов, список «где используется» для файлов.
- **Карточка имени.** У файла, помимо версий, есть папка (один уровень), теги, лицензия, требования к файлу и промпт для внешнего ИИ. Это сохраняется сразу на все версии имени (`POST media/card`) и копируется, когда загружают следующий файл. Запроса к генератору нет. Изображения по-прежнему не загружаются: карточка описывает уже лежащие GLB и то, какого файла ещё не хватает.
- **3D-просмотр в админке.** three.js (MIT, локальная копия `admin/vendor`). Показывает любую версию, проигрывает анимации модели и анимации из других файлов, скелет, скорость; назначение анимации на события боя пишется в `visual.anims` / `visual.anim_files`.
